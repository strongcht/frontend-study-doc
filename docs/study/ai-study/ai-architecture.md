# AI 底层架构

下图展示了从基础大模型到智能体应用的完整 AI 系统架构。

---

## 五层架构总览

该架构包含五个层级，从底层到顶层依次为：

### 基础层（模型）

- **核心组件**：LLM & Token、Transformer 架构、Token 化、注意力机制
- **核心作用**：AI 的底层计算核心，负责文本理解、Token 预测、语言生成
- **典型能力**：自然语言理解、文本生成、上下文建模、概率预测

### 上下文层（记忆）

- **核心组件**：Context Window、Prompt、Memory、RAG
- **核心作用**：管理模型输入上下文，负责短期记忆、长期记忆、外部知识注入
- **典型能力**：Prompt 控制、会话记忆、知识检索、上下文增强

### 能力扩展层（工具）

- **核心组件**：MCP、Tool Calling、API、Database
- **核心作用**：让 AI 不止聊天，通过工具调用扩展真实世界操作能力
- **典型能力**：联网搜索、代码执行、数据库查询、API 调用

### 智能体层（决策）

- **核心组件**：Agent、Explore、Plan、Act
- **核心作用**：AI 自主决策大脑，负责目标理解、任务拆解、规划与闭环执行
- **典型能力**：任务规划、多步骤推理、自主决策、闭环执行

### 应用层（行动）

- **核心组件**：Agent Skill、Workflow、Automation
- **核心作用**：面向具体业务场景，将 Agent 能力封装为可落地产品
- **典型能力**：自动化工作流、行业AI助手、企业智能系统、AI SaaS应用

## 核心名词释义

- **Transformer**：当前大模型核心架构，通过自注意力机制建立 Token 之间关联关系。
- **Token**：模型处理文本最小单位，可为子词、单词、字符或符号。
- **Prompt**：给到模型的输入指令，用来设定角色、控制行为、规范输出格式与目标。
- **RAG**：检索增强生成，先检索外部专业知识库，再交由 LLM 整合生成精准答案。
- **MCP**：模型上下文协议，统一 AI 与工具、数据库、外部服务的通信标准。
- **Agent**：在 LLM 基础上叠加目标、规划、执行能力的自主智能系统。
- **Tool Calling**：模型主动识别需求、调用外部工具完成实际操作，不局限纯文本回复。
- **Memory**：为 AI 提供短期会话记忆加长期持久记忆，解决上下文遗忘问题。

## AI Agent 完整运行流程

一个完整的 AI Agent 运行流程包含以下六个步骤：

### 步骤 1：用户输入

用户下发指令 Prompt，进入上下文窗口 Context Window。

### 步骤 2：记忆增强

系统联动 Memory 会话记忆与 RAG 外部知识库，补充上下文与专业知识。

### 步骤 3：LLM 推理

通过 Transformer 架构对 Token 序列做注意力计算，进行语义理解与初步生成。

### 步骤 4：Agent 规划

智能体自主判断、拆解任务，决策是否需要多步骤执行或调用外部工具。

### 步骤 5：工具执行

基于 MCP 协议，调用 API、数据库、搜索引擎等外部能力完成实操。

### 步骤 6：输出结果

汇总工具返回数据与模型推理结果，整理后返回用户，同时写入记忆存档。

---

## 运行流程示意

```
用户输入 Prompt
      ↓
进入 Context Window（上下文窗口）
      ↓
联动 Memory + RAG（记忆增强）
      ↓
LLM + Transformer 推理（语义理解）
      ↓
Agent 规划（任务拆解、决策）
      ↓
Tool Calling（MCP 协议调用外部工具）
      ↓
输出结果 + 写入记忆存档
```

## 各层之间的依赖关系

```
┌─────────────────────────────────────────────┐
│            应用层（Workflow、Skill）          │  ← 面向业务场景
├─────────────────────────────────────────────┤
│          智能体层（Agent、Plan、Act）         │  ← 自主决策
├─────────────────────────────────────────────┤
│       能力扩展层（MCP、Tool Calling）        │  ← 工具调用
├─────────────────────────────────────────────┤
│      上下文层（Prompt、Memory、RAG）         │  ← 记忆管理
├─────────────────────────────────────────────┤
│     基础层（LLM、Transformer、Token）        │  ← 底层计算
└─────────────────────────────────────────────┘
```

每一层都建立在下层的基础之上：

- **基础层**为所有上层提供语言理解和生成能力
- **上下文层**在基础层之上管理信息流和知识注入
- **能力扩展层**让 AI 从"只能聊天"进化为"能做事"
- **智能体层**赋予 AI 自主规划和决策的能力
- **应用层**将以上所有能力封装为用户可直接使用的产品

---

## 总结

AI 底层架构的五层模型清晰地展示了从芯片到应用的完整技术栈：

| 关注点 | 核心问题 |
|--------|---------|
| 基础层 | AI 如何理解语言？ |
| 上下文层 | AI 如何记住信息？ |
| 能力扩展层 | AI 如何与外部世界交互？ |
| 智能体层 | AI 如何自主决策？ |
| 应用层 | AI 如何服务用户？ |

理解这个架构有助于在实际开发中准确定位问题所在——是模型能力不足（基础层）、上下文不够（上下文层）、缺少工具（能力扩展层）、规划不合理（智能体层），还是产品封装不到位（应用层）。
